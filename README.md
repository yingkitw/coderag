# coderag

**Retrieval engine for codebases.** Syntax-aware chunking → pluggable
embeddings → persistent hybrid search, packaged as a Rust library and a CLI.

It runs fully offline out of the box (deterministic local embeddings, zero
network) and upgrades to any OpenAI-compatible embedding API with one flag.
Indexes are incremental (content-hash keyed), gitignore-aware, and stored in a
single SQLite file.

```
$ coderag init && coderag index
```

## Why another RAG crate

Most "code RAG" demos chunk files by line count and assume an embedding API.
coderag treats retrieval as an engineering problem:

- **Chunks respect the grammar.** Files are parsed with tree-sitter; chunks
  are definitions (functions, classes, traits, ...). Oversized definitions are
  decomposed into nested definitions (methods of an impl/class), which carry
  the parent header (`impl Engine {`) as context. Doc comments and decorators
  stay attached to what they document, the file preamble (imports, module
  docs) rides along on every chunk, and *no code is silently dropped* —
  leftover spans become explicit `block` chunks.
- **Indexing is incremental.** Every file is blake3-hashed and diffed against
  the store: unchanged files cost nothing, edits re-embed only the edited
  file's chunks, deletions are cascaded. A no-op `coderag index` run is
  instantaneous.
- **It works offline.** The default provider is a deterministic hashed
  bag-of-words embedder — no API key, hermetic tests, stable vectors forever.
  Switch to `--provider openai` (or Ollama/vLLM/LM Studio via `base_url`)
  for real semantic quality.
- **Search is hybrid and explainable.** `score = 0.85·cosine + 0.15·lexical
  + symbol bonus`, with per-file diversity caps. Every hit reports its
  cosine and lexical components.

## Layout

```
Cargo.toml                 workspace
crates/coderag             the library
  src/chunking.rs            tree-sitter definition-aware chunker
  src/langs.rs               grammar registry (feature-gated per language)
  src/embedding/             provider trait + local & openai backends
  src/store/sqlite.rs        SQLite persistence (files, chunks, vectors)
  src/engine.rs              incremental pipeline + hybrid search
  src/config.rs              .coderag/config.toml
  src/tokens.rs              identifier-aware tokenizer
crates/coderag-cli         the `coderag` binary
```

## CLI

| Command | What it does |
|---|---|
| `coderag init [--provider local\|openai] [--model M] [--dim N]` | create `.coderag/` (config + empty index) |
| `coderag index [--rebuild] [--json]` | incremental index pass |
| `coderag search QUERY [-k N] [--max-per-file N] [--min-score F] [--full] [--json]` | hybrid search |
| `coderag status [--json]` | files, chunks, languages, provider signature, db size |
| `coderag watch` | re-index on change (debounced, ignores `.coderag/`, `target/`, ...) |
| `coderag config [--json]` | effective configuration |
| `coderag languages` | grammars compiled into this binary |

Global flag `--project DIR` selects the project root (default: cwd).

## Configuration

`.coderag/config.toml` — generated by `coderag init`, fully commented by
example:

```toml
[embedding]
provider = "local"          # or "openai" (any /v1/embeddings endpoint)
model = ""                  # empty = provider default
dimensions = 256            # must stay fixed; changing requires --rebuild
batch_size = 64
# base_url = "https://api.openai.com/v1"   # or OPENAI_BASE_URL env
# api_key_env = "OPENAI_API_KEY"

[index]
max_chunk_chars = 1600
min_chunk_chars = 24
preamble_chars = 512
max_file_bytes = 1500000
skip_dirs = ["target", "node_modules", "dist", "build", ...]

[search]
top_k = 8
max_per_file = 3
lexical_weight = 0.15       # 0 = pure vector, 1 = pure lexical
min_score = 0.0
```

The index records a provider signature (`provider:model:dimensions`); opening
an index built with a different setup fails fast with a `--rebuild` hint
instead of silently mixing vector spaces.

### sqlite-vec candidate mirror (optional feature)

Build the CLI/library with `--features ann` to route unfiltered queries
through a [sqlite-vec](https://github.com/asg017/sqlite-vec) `vec0` virtual
table kept transactionally in sync with the chunk rows, instead of loading
every embedding into Rust:

```console
$ cargo install coderag-cli --features ann   # or: cargo build --features ann
$ coderag status
ann       : sqlite-vec (feature on)
$ coderag search "retry backoff" --no-ann    # force the exact scan anytime
```

Filtered queries (`--lang`, `--symbols-only`) always use the SQL scan path,
which applies predicates before embeddings load. On the golden benchmark the
two strategies return identical results; on larger corpora the two-stage
retrieve-rerank can diverge slightly from the exact scan (measured
recall@10 ≈ 0.94 at a 500-candidate pool on a 1.2k-chunk synthetic corpus) —
`--no-ann` is the exact escape hatch. sqlite-vec 0.1.x performs exact SIMD
scans; the feature's real payoff arrives when approximate indexes land
behind the same seam.

### Using OpenAI (or Ollama, vLLM, ...)

```console
$ export OPENAI_API_KEY=sk-...
$ coderag init --provider openai --dim 1536 --force
$ coderag index --rebuild
```

For a local LLM server, set `OPENAI_BASE_URL` (or `base_url` in the config)
to e.g. `http://localhost:11434/v1` and pick a model it hosts. Batching and
exponential-backoff retries on 429/5xx are built in.

## Library usage

```rust,ignore
use coderag::config::CodeRagConfig;
use coderag::engine::{Engine, IndexOptions, SearchOptions};

let config = CodeRagConfig::default(); // offline local provider
let mut engine = Engine::open(project_dir, config)?;

engine.index(IndexOptions::default()).await?;
let hits = engine.search("retry backoff delay", SearchOptions::default()).await?;
for hit in hits {
    println!("{:.3} {}:{} {}", hit.score, hit.chunk.path, hit.chunk.start_line, hit.chunk.symbol.as_deref().unwrap_or("-"));
}
```

Implement `EmbeddingProvider` (one async method) to plug in any embedding
source; the store and engine don't care where vectors come from.

## Languages

Rust, Python, JavaScript, TypeScript, TSX, Go, Java, C, C++ — each behind a
cargo feature (`lang-rust`, `lang-python`, ...) so downstream builds can
compile a slim binary. `coderag languages` lists what your binary has.

## Design notes & honest limits

- **Vector search is brute-force cosine** over vectors loaded from SQLite.
  Exact, dependency-free, and fast for codebase scale (tens of thousands of
  chunks in milliseconds with rayon). ANN indexes (HNSW, sqlite-vec) are the
  upgrade path once you're past ~10⁶ chunks — the store module is the seam.
- **The local provider is lexical**, not neural: it matches vocabularies, not
  meaning. It's there so the tool works with zero setup and the tests are
  hermetic. For real semantic retrieval, use the OpenAI provider.
- Chunking is heuristic around the edges (anonymous functions, giant match
  arms), but it never loses bytes and never splits mid-line.
